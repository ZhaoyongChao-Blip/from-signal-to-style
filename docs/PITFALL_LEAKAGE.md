# t4_lgb.py 泄漏事故记录（2026-11-11）

## 现象

`t4_lgb.py --walk` 首轮跑出 **train AUC 0.949 / valid AUC 0.940 / walk-forward IC 0.81**。
单变量 IC 最高的因子 `log_amt` 才 0.54 AUC、corr(factor, fwd5) 最大 0.53（`ret_5` 只有 −0.026），
所有因子都是 `shift(+n)` 纯前定构造。**AUC 与单因子信息量差了两个数量级 ⟹ 一定有列泄漏。**

## 根因

`feat_cols(df)` 的实现是：

```python
def feat_cols(df):
    return [c for c in df.columns if c not in DROP and df[c].dtype.kind == "f"]
```

「不在 DROP 里 + 是浮点」——这个白名单是**反向定义**的：任何后加进来的浮点列都会自动进特征。
`t3_features.py` 在 215 行往面板里 join 了三个**未来**指数收益：

```python
d = d.assign(**{f"idx_{cname}_fwd5": (d["close"].shift(-5) / d["close"] - 1)})
```

于是 `idx_000300_fwd5 / idx_000905_fwd5 / idx_000852_fwd5` 三列（**未来 5 日指数收益**）
静默进入了 46 个因子之外的特征集。`y_exc` 的定义是 `fwd5 > 当日全市场等权 fwd5`，
与大盘未来收益高度相关 ⟹ 模型直接读到了标签的组成部分。
另外 `y_exc_nzt`（标签本身，float/转 int 后仍是数值）也在 50 个「特征」里。

实测泄漏列清单（修复前 50 个特征）：

```
idx_000300_fwd5, idx_000905_fwd5, idx_000852_fwd5, y_exc_nzt
```

## 修复

```python
LEAK_PREFIX = ("idx_",)
LEAK_EXACT  = {"y_raw", "y_exc", "y_exc_nzt", "y_perm"}

def feat_cols(df):
    return [c for c in df.columns
            if c not in DROP and c not in LEAK_EXACT
            and not c.startswith(LEAK_PREFIX)
            and df[c].dtype.kind == "f"]
```

修复后 46 个特征，与 `t3_features.py` 的 `feat_meta.json` 完全一致。
重跑：train AUC 0.691 / valid 0.527 / WF IC 0.057~0.084。

## 验证泄漏已消失的三个对照

| 检验 | AUC | 结论 |
|---|---|---|
| 全量 3.94M 行，46 特征 | 0.5463 | 正常水平 |
| 全量 + **打乱标签** | 0.5015 | 无泄漏（≈0.5） |
| 去掉价格水平类特征 | 0.5370 | 水平类只贡献 ~0.01 |

## 教训（要写进流程）

1. **特征白名单必须是正向列出的**，不能「排除法」。用 `feat_meta.json` 的 `factors` 列表当唯一真源，
   在 `t4/t5/t6` 里 `assert` 特征数 == 46 且不含 `fwd`/`idx_`/`y_` 前缀。
2. **任何 AUC > 0.65 的二分类日频选股模型，先当泄漏处理**，不要先庆祝。
   本机可用的排查顺序：① 单变量 AUC 上界 ② 打乱标签 ③ 子样本 vs 全样本一致性 ④ 打印 `feat_cols` 实际清单。
3. **打乱标签这一步必须在写结果文件之前跑**，成本 2 分钟。
4. 面板宽表（74 列）里混着特征/标签/辅助量，靠集合排除极易漏。
   `t3_features.py` 应只把特征列写成带前缀的 `f_`，从命名上隔离。

# 第二轮新坑（2026-11-12）

## 4. `amount / volume` 不是股价
`volume` 单位是「手」= 100 股，所以 `amount / volume` 是「元/手」。
`t5e_capacity.py` 一度算出「picks 中位股价 **706.94 元**」，真实是 7.07 元。
同理 `turnover` 是百分数（1.04 表示 1.04%），算流通股数要 `volume*100 / (turnover/100)`。
**判据：任何「价格」派生量，用 `raw_close` 对拍，中位比值应在 1.0 ± 0.05。**

## 5. `parse_dates=['date']` 在索引列上报 KeyError
`t5_backtest.py` 写 nav 时用 `nav.to_frame("nav").to_csv(...)`，日期落成**无列名的索引列**。
读取时必须 `pd.read_csv(path, index_col=0, parse_dates=True)`，写 `parse_dates=['date']` 会 KeyError。

## 6. `groupby` 在 category 列上的空组
`t6_diagnose.py` 的 D3 用 `for k, g in d.groupby("fwd5_has_zt")` 时，
t3 重建面板后 fwd5_has_zt 一度全 0（另一处 bug 修复后正常）。
但同一写法在 **category 列**上会多出 NaN 组并让 `for k,g` 迭代到 NaN，
必须 `groupby(..., observed=True)`。

## 7. 重叠标签把 t 值抬高约 √5 倍（本轮最重要的口径坑）
`fwd5` 在相邻 5 个交易日里高度重叠，「逐日 IC 序列」不是独立样本。
naive t = IC/σ×√n = **18.68**（n=443）；按每 5 天取 1 天（stride=5，n=89）后 **t = 8.30**。
比值 2.25，接近 √5=2.24。
**规则：任何用重叠窗口标签算的 IC / t 值，必须再做一次 stride=h 的无重叠版。**
既有的「IC 0.154（+43%）」这类比较若跨了不同 n，也要先统一到无重叠口径再比。

## 8. 参数网格里「一致性差」先怀疑不是参数敏感性
`t5b_robust.py` 网格里 y_exc 在 H=20 时 5 个 K 全部变成 +3.6%~+10.0% 超额，
而 H=5/H=10 全是 −16%~−30%。**gap 26 个百分点**。
如果信号是真的，持有期只该让换手成本下降、超额略升；从「大幅跑输」跳到「明显跑赢」
更可能是 20 日窗口恰好对齐了某段风格行情。
**规则：网格里出现符号翻转且 gap > 15pp 的格子，不写进结论，只当作「需要解释的异常」。**

## 9. 小样本口算 p 值会错
HANDOFF 里写「Sharpe 0.446 约在第 92 百分位（p≈0.08）」，
实际跑完 200 次 placebo 后是 **98.5 百分位（p=0.015）**。
**规则：p 值一律从 `output/m5_placebo.csv` 数出来，不口算。**

## 10. 「最近邻/匹配」构造的对照组自带正偏差（2026-11-12 下午，本轮最值钱的教训）

**现象**：t7d 想做「风格匹配对照组」——每个调仓日，在候选池里找与 picks 的 4 个风格因子
标准化欧氏距离最近的 30 只，买入当基准。结果对照组年化 **27.87%**，比模型本身（18.37%）还高 9.5pp。
第一反应：「模型在负向选股」。

**根因**（t7e 的 placebo 揭穿）：把 picks 分数换成随机数，同一套匹配流程跑 100 次，
零分布年化均值 **19.28%**；而完全随机选 30 只的零分布只有 **15.97%**。**匹配构造自带 +3.3pp。**

机制：当 picks 的风格向量整体偏离截面均值（例如都在 log_amt 的低分位）时，
「距离最近」的候选会在**所有维度上同时向 0 收缩**——它不必和 picks 一样小，
只要在每个维度上都「更靠中间」就距离更近。结果匹配组系统性换成一批风格更中庸的股票，
这批股票在 2024-2025 这段恰好表现更好。

**修复**（t7f）：改用**同格子分组**而不是最近邻。每个调仓日对 4 个因子各分 5 档 → 5⁴ 格子，
picks 落在哪格，就在**同一格子**里取其余股票等权为基准。placebo 复验：随机 picks 跑 5 次，
同格子差 −0.056% / +0.002% / +0.004% / +0.052% / −0.059%，t∈[−1.18, +0.82]，**偏差消失**。

**规则**：任何「匹配 / 近邻 / 分层 / 倾向得分」构造的基准，**必须先跑随机分数的零分布，
确认零分布均值 ≈ 真随机**。不通过就不能用。分层（格子）优于近邻，因为格子是「装桶」不是「收拢」。
> 这条与第 8 条同源：上次是「分档单调 ≠ 结论稳健」，这次是「对照组自带偏差 ≠ 模型失败」。

## 11. 「能否成交」与「算收益」必须用两套价格（2026-11-12 下午）

**现象**：t5/t8 用 `adj_open`（后复权开盘价）判断「开盘是否涨停」（`adj_open >= 前收×(1+limit)`）。
跨除权日复权价跳变，会把没涨停的票误判成涨停/反之，且**系统性偏向高频涨停的小票**。
改成「原始价判成交、复权价算收益」（t8c）后：y_neut 年化 **18.37% → 11.68%（−6.7pp）**，
y_exc 4.36% → 4.81%（+0.45pp）。买不进占比：y_neut 中位 3.3%、90 分位 16.7%。

**规则**：涨跌停判定、最小变动价位、成交量阈值等**制度性约束一律用原始价**；
收益率、净值、组合估值一律用**复权价**。两者不能混在一个表达式里。

## 12. 「累计收益重算」会吃掉空仓期收益（2026-11-12 下午）

**现象**：t8i 为了「修掉重复计收益」，改成「持仓从 buy_px 到今日 close 的累计收益」重算净值。
结果 hold=10 报 33.03%，比已验证口径（逐日收益累乘）的 26.78% 高 **6.25pp**。

**根因**：`pos` 为空的交易日（买不进、或候选不足），代码沿用上一个 `nav_now`，
**空仓期的收益变化被抹平**，净值序列在空仓→建仓的切换处不连续，相当于白送了收益。

**规则**：回测净值**只允许一种写法——逐日收益累乘**（`cash *= (1 + Σ w·r)`）。
任何「按持仓期累计收益重算」的写法都要用「已验证口径跑同一格」对拍，
差异 >1pp 就说明有 bug。这次靠 t8j 对拍才发现。

## 13. 「单次换手」不是成本，`年化换手 = 单次 × 频率`（2026-11-12 下午）

**现象**：3亿池单次换手 5日 56.7% → 10日 66.7% → 20日 70.0%，随持有期单调上升，
看起来「持有越久越差」。

**真相**：成本由年化换手决定（t8k）：
- 5日：56.7% × 50.4 轮 = **28.56 倍/年**
- 10日：66.7% × 25.2 轮 = **16.80 倍/年**（成本只有 5 日的 59%）
- 20日：70.0% × 12.6 轮 = **8.82 倍/年**

单次换手上升只是「调仓次数减少」的副作用。**规则：报换手率时必须给年化值，单次值单独出现会误导。**

## 14. 用「当日信息」筛的池子，不能用「当日收益」衡量（2026-11-12 下午）

**现象**：t8f 算「amount≥3亿 池等权」，用当日 amount 筛池、用当日 `adj_close.pct_change()` 算收益，
得出**年化 220.40%**。

**根因**：成交额放量的那天恰好也是涨幅最大的那天 → 池子是按结果筛出来的（前视）。
修正为「dt 日筛池 → t+1 开盘买 → t+2 开盘卖」后，数值回到合理区间。

**规则**：任何「池 / 组合 / 分组」的收益衡量，筛选时刻必须严格早于收益起点。
这条与第 11 条（价格口径）是两个独立的坑，都出在「算得出来但口径错」。

# 论文阶段（2026-11-12 18:00~18:35）新增

## 15. 两个「应当不同」的派生量逐位相同 —— 一定是接错了源，不是巧合（2026-11-12 晚）

**现象**：`paper/numbers.json` 里 `ann_y_exc_2kw_5d` 与 `ann_y_neut_2kw_5d` **逐位相同**
（0.11680302737066683），`vol_*`、`sharpe_*`、`mdd_*` 也全部相同。

**根因**：两个 key 指向了两份文件 `m8j_nav_2千万_5d.csv` 与 `m8d_nav_V1a.csv`，
但这两份文件的 max|diff| = **0.0** —— 它们都是 `models/lgb_y_neut.txt` 在同一资金池下的回测，
只是被两个脚本各跑了一遍。真正的 y_exc 真实价回测是 `m8c_nav_y_exc.csv` = **4.81%**。

**为什么危险**：如果论文正文引用了那个 key，就会写出「y_exc 11.65%、y_neut 11.65%，
中性化零效果」这种自相矛盾的结论。本次正文碰巧用的是硬编码的正确值 11.68%/4.81%（来自 m7d/m8c 的 md），
但**断言表和正文已经脱钩了**——这才是真正的问题。

**规则**：
① 任何 `numbers.json` 级别的断言表，必须做**两两对撞**：同一分组下（不同标签 / 不同参数 / 不同处理）
   应当不同的净值序列，逐位相同即报错。脚本 `xcheck.py` 的 X1 段实现了这个检查。
② 数字「看起来对」不等于「接对了源」。**接错源的数字往往和正确值量级相同**，肉眼看不出。

## 16. 超额收益有三种口径，混用会让同一张表自相矛盾（2026-11-12 晚）

同一个组合对同一个基准，至少有三种「超额」：

| 口径 | 定义 | 经济含义 |
|---|---|---|
| **复利差** | `prod(1 + r_p - r_b)^(252/n) - 1` | 1:1 每日再平衡多空对冲组合的收益 |
| **年化差** | `ann_p - ann_b` | 只做多视角，单纯两个年化收益相减 |
| **累计差** | `cum_p - cum_b` | 某段区间的累计收益相减（只看归因，不是年化率） |

**实测差异**（3 亿池 5 日持有，15bp；基准等权 21.11%）：

| 窗口 | 年化 | 复利差 | 年化差 | 差 |
|---|---|---|---|---|
| 1 日 | 21.17% | **−3.41%** | **+0.06%** | 3.47pp |
| 3 日 | 30.11% | +3.79% | +9.00% | 5.21pp |
| 5 日 | 29.71% | +3.35% | +8.60% | 5.25pp |

**1 日窗口两种口径符号相反**。审稿人一算 `29.71 − 21.11 = 8.60` 却发现表里写 `+3.35`，
会直接质疑数据造假。

**为什么会差这么多**：口径 A 是「组合日收益 − 基准日收益」的复利，组合波动 20.91%、
基准 25.65%，两者的波动差会通过 `prod(1+x)` 的凹性产生额外拖累（实测 2.35pp）。
口径 B 完全不含这个效应。

**规则**：
① 论文里**只允许一种主口径**，其余口径必须单列一栏并写明定义。
② 表注必须写清 `Excess = ?`，不能只写 "Excess vs. market"。
③ 判断用哪个：问「这是只做多自有资金，还是 1:1 对冲」。前者用年化差，后者用复利差。
   本文全篇叙述是只做多（「小盘崩盘时它不跌」），所以主口径必须是年化差。

## 17. 表格拆页与 markdown 标记残留 —— 只有打开成品才看得见（2026-11-12 晚）

**现象 1**：Table 8 的表头 + 前两行在 p7 底部，第三行掉到 p8。
**现象 2**：Table 9/10 的表题末尾打印出字面 `**`。
**现象 3**：文档最后一段打印出字面 `\n`（用 python 写文件时把转义串写进了正文）。

**根因**：
- 拆页：python-docx 建表后默认允许跨页，需给**每个** `w:tr` 加 `w:cantSplit`，
  且除最后一行外所有单元格段落设 `keep_with_next=True`。
- `**`：题注处理用 `txt.strip("*")` 只剥首尾，中间那对留在正文里。应 `txt.replace("**","")`。
- `\n`：`s.rstrip() + " ...repository.\n"` 在 heredoc 里被当成字面反斜杠 n 写入。

**规则**：这三类问题属性检查（段落数、表格数、字体名）**一个都查不出来**。
必须：
① 渲染成 PDF，用 `fitz` 提取每页图像 bbox 判断图是否被裁；
② 用长横线数量核对三线表是否被拆（每表应为 3 条，N 个表 = 3N 条）；
③ 全文搜 `**`、`\n`、`鈥`、`U+FFFD` 这类「不该出现在成品里」的字符；
④ 逐页看墨迹边界，确认没有越出版心。

这正是 USER.md 里「只检查属性不看成品」那条坑的**第 4 次复现**。
